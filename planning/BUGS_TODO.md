# Bugs found during the November 2026 docs review

These are library problems noticed while checking every claim in the student docs against a running site. None of them is fixed here. The docs pass only wrote around them, and each item names the pages that describe the current behavior so they can be corrected with the fix.

Update, later on 14 November 2026: the items marked `[x]` were fixed in a follow-up pass, with tests, and the docs pages they name were corrected. The unmarked items are waiting on a decision. A bold note at the end of an item says what part of it is done.

Update, 15 November 2026: the remaining items were decided and, apart from browser validation on a `Button` click (left off on purpose), implemented with tests. Each item's last bold note says what was done. Problems noticed along the way and not fixed are listed under "Noticed while fixing" at the end.

How they were found: Drafter 2.2.1 source on 14 November 2026, Windows 11, headless Chromium driven by Playwright against the dev server and against compiled sites. Line numbers are from that source and will drift.

Each item ends with how well it is established:

- **(browser)** seen in a real page.
- **(ran)** reproduced by running Python, with no browser.
- **(source)** read in the code only.
- **(unconfirmed)** seen once or not diagnosed. Reproduce it before fixing.

Some items overlap with `post_hackathon26_items.md`; those say so.

# Students will hit these

- [x] **Reloading the tab after a form submit shows an error page.** The address bar keeps `?route=<last route>`. A reload resets the state and runs that route again with no form values, so a route with a required parameter stops with "Problem With the Route's Arguments" ("expects a value for parameter 'new_name'"). "Return to Index Page" recovers. Same on the dev server and on a compiled site. Related: values in the address are never passed along, so `?route=greet&who=Ada` and `/greet?who=Ada` both run `greet` without `who`. Possible fixes: fall back to `index` when the reloaded route is missing required arguments, or keep `?route=` off requests that carried form data. Docs: `docs/help/troubleshooting.md` ("Reloading the tab does not go back to the first page"), `docs/help/faq.md`, `docs/reference/route.md#opening-a-site-on-a-route`. (browser) **Fixed 15 Nov: when the route in the address needs values it will not get, the first page opens with a fresh state, `route` is taken out of the address, and one warning says why. Values in the address are still not passed to routes.**
- [x] **"Reload Entire Application" on an error page never settles.** The link goes to `--reload`, the address keeps `?route=--reload`, and every load runs it again: 22 reloads in 30 seconds with browser history on. Opening `?route=--reload` directly does the same. Docs: `docs/reference/route.md#built-in-routes` says only that `--reload` is not meant as a button target. (browser)
- [x] **`Download` with text content damages the file.** `components/files.py:102` builds `data:<type>,<content>` without escaping. A `#` ends the file there, `%41` arrives as `A`, and trailing whitespace or a final newline is dropped. Bytes content arrives intact. Percent-encoding or base64 would fix it. Docs: the Notes bullet in `docs/reference/components/input/download.md`, and the save-and-load recipe in `docs/add/files.md`, which calls `.encode("utf-8")` to avoid this. (browser, Chromium only)
- [ ] **Many input keywords silently become CSS.** A keyword missing from a component's `KNOWN_ATTRS` is rendered as a style, for example `style="max: 10; min: 0; required: True"`, so `TextBox("age", kind="number", min=0)` has no lower bound and nothing warns. Missing keywords by component (`components/forms.py`, `components/files.py:140`): **Partly fixed: the keywords listed above are now real attributes, `RadioButtonGroup` passes `required` and `disabled` to its radio buttons, and `autocomplete` keeps its value. Still open: browser form validation does not run on a `Button` click.** **Decided 15 Nov: browser validation on a `Button` click stays off for now, so existing sites do not change. May be revisited.**
    - `TextBox`: `required`, `min`, `max`, `step`, `disabled`, `readonly`, `autocomplete`, `list`
    - `TextArea`: `maxlength`, `minlength`
    - `SelectBox`, `ColorPicker`, `FileUpload`: `disabled`
    - `CheckBox`, `RelatedCheckBox`: `required`, `disabled`
    - `DateInput`, `DateTimeInput`, `TimeInput`: `min`, `max`, `step`, `required`, `disabled`, `readonly`
    - `Slider`: `disabled`, `list`
    - `RadioButtonGroup`: everything. `KNOWN_ATTRS` is empty and keywords land on the wrapper `div`.

    Two connected problems. Browser form validation never runs on a `Button` click, so even the recognized `required`, `pattern` and `minlength` do not stop the route (`maxlength` does limit typing). And `autocomplete` is in `BOOLEAN_ATTRS`, so `TextArea(autocomplete="off")` renders a bare `autocomplete`. Docs: every page under `docs/reference/components/input/` now lists the attributes that work. (ran and browser)
- [x] **A missing local module is installed from PyPI by name.** When `import helpers` finds no `helpers.py` beside the program (typically a file that was never uploaded to the deployed site), the browser installs the unrelated PyPI package called `helpers` and the student gets a confusing error from that package. A message saying the local file is missing would help. Docs: the deployed-import entry under Common problems in `docs/add/files.md`. (browser) **Fixed 15 Nov: a debug-panel warning names any library an import was filled with from PyPI, and a following "cannot import name" error gets steps about the missing file.**
- [x] **A tab left from an earlier run never reconnects.** After the same file is run again and takes over the port, the old tab keeps running the old code, ignores saves, and says nothing. There is no reconnect for the dev websocket (`js/src/pyodide.index.tsx:570-572`). Either reconnect, or have the takeover message tell the student to reload the tab. Docs: `docs/help/troubleshooting.md` ("The browser shows an old or different app"), `docs/start/make-a-change.md`. (browser) **Fixed 15 Nov: the tab retries for two minutes and reloads when the program is back; after that it shows a "Disconnected" notice that can be closed.**
- [x] **A button that points at a missing route gets a confusing error page.** The title is "Unusable Value", the generic title for a `ValueError`. The message calls the button a "Link" (`components/links.py:187-197`; already in `post_hackathon26_items.md`). The hint says to pass the route function itself, which the docs do not teach and which raises `NameError` when a test runs above the target's definition. The same generic title is used for Drafter's other untitled student errors: page content, a `SelectBox` default that is not an option, and a bad `Header` level. Docs: `docs/start/make-a-change.md` quotes the current text, and so does `docs/help/errors/route-not-found.md`. (browser) **Fixed 15 Nov: the page is titled "Button Points to a Missing Page" (or "Link ..."), and the steps no longer suggest passing the function. Page content, `SelectBox` default and `Header` level errors have their own titles too.**
- [x] **Unused values fill the debug panel with warnings.** Every form field on a page warns for any route that does not take it ("The form field 'X' was sent to 'Y', but the function has no matching parameter."), including a Cancel button on a form page. Event values do the same: the docs' own `Timer` example, `times_up(state)`, produces two warnings each time it finishes ("The event value 'duration' was sent to..."). Already in `post_hackathon26_items.md`. Docs: `docs/help/errors/missing-parameter.md` explains the warning. (browser) **Fixed 15 Nov: a form field or event value warns only when its name is close to a parameter that received nothing. An unused `Argument(...)` still always warns.**
- [x] **When `drafter.pyodide.js` fails to load, the page looks ready but is dead.** The loading screen is removed, the buttons do nothing, and the only message is a `TypeError` in devtools. (browser)
- [x] **`input()` in a route shows a browser prompt with no question.** The text passed to `input` is not shown. (browser) **Fixed 15 Nov: the prompt shows the question; Cancel gives an empty string.**

# Settings and the command line

- [x] **Config files crash.** `--config-file` and `DRAFTER_CONFIG_FILE` end in `RecursionError` before anything starts, through `drafter`, `python -m drafter` and `python main.py`. `BaseConfiguration.load_from_file` (`config/base.py`) calls the patched `builtins.open` (`files/opening.py:181`), which calls `get_system_configuration()` while the configuration is still being built. Docs: config files were left out of `docs/reference/start-server.md#where-settings-come-from` and removed from `docs/reference/live-reload.md`. (ran)
- [x] **Six environment variables are ignored.** `DRAFTER_PORT`, `DRAFTER_HOST`, `DRAFTER_USE_RELOADER`, `DRAFTER_OPEN_BROWSER`, and the ones for `inline_py` and `serve_adjacent_files` are always overwritten by argparse defaults (`config/app_server.py:189-225`). The watch flags use `default=None` and work. Docs: `docs/reference/start-server.md` and `docs/reference/live-reload.md` say these have no effect. (ran; `DRAFTER_HOST` source only)
- [x] **`DRAFTER_FRAMED=false` leaves the frame on.** The value is read as a string (`config/client_server.py:187`), so `"false"` is truthy. (source)
- [x] **`--zip-output` does nothing.** The flag is accepted and `zip_output` is stored, but the builder never reads it. Docs: the row was removed from `docs/reference/cli.md`. (ran) **Fixed 15 Nov: writes `<output folder>.zip` next to the output folder.**
- [x] **`--reset` resets the main server, not the one handling the request.** `router/defaults/reset.py:16-17` calls `get_main_server()` and has a TODO about it. A normal single app works. With a second `ClientServer` the state is not reset, which probably includes embedded docs demos. Docs: the "Start over" example in `docs/reference/route.md` is a plain fence for this reason. (ran)
- [x] **A misspelled `start_server` keyword is ignored silently.** No terminal message and no debug-panel warning. Docs: `docs/reference/start-server.md` warns about it. (browser) **Fixed 15 Nov: a warning with a "Did you mean" suggestion in the terminal and the debug panel; the site still starts. Drafter 1 option names stay quiet.**
- [x] **A configuration function and a `start_server` keyword that disagree give a split result.** The tab title and debug panel followed the functions while the theme followed the keyword. (browser) **Fixed 15 Nov: settings made before the site started are no longer applied a second time, so the last one written wins and `start_server` is last. This also fixed `set_website_framed(False)` above `start_server` being undone at load.**
- [x] **`set_website_style("water")` on its own leaves an error in the debug panel**: "Drafter had trouble syncing your Python code with the browser" / "Could not apply the new theme to the page", although the theme is applied. This is the same symptom as the almond item in `post_hackathon26_items.md`. (browser, headless Chromium; unconfirmed elsewhere)
- [x] **The port check misses some occupied ports on Windows.** With `python -m http.server 8136` running (bound to `::`), `main.py --port 8136` started with no message and both listened on the port. `port_is_free` in `app/ports.py` is a plain bind test and only caught an occupant bound to `127.0.0.1`. (ran)
- [x] **`add_website_file` reports problems badly.** A missing file named at module level shows a raw traceback, so the friendly "Did you mean" steps are never seen. Wrong letter case is not detected on Windows, and the copy takes the spelling in the code. A folder name is rejected as "file not found". Docs: `docs/reference/site-config.md` promises suggestions. (ran) **Fixed 15 Nov: a Drafter error at the top of a file prints the friendly box with a "Where:" line instead of a traceback; a name that differs from the file only in capital letters is an error; a folder is accepted.**
- [x] **`set_assertion_defaults(True)` is accepted positionally and sets `precision=True`.** (ran)
- [x] **The takeover shutdown message is wrong.** When a new run stops an earlier one, the earlier one prints "Stopping the server because the browser asked it to." (ran)

# Components, pages and tests

- [x] **Every `Link` renders `style="name: --submit-button"`.** `name` is set at `components/links.py:270` but is missing from `Link.KNOWN_ATTRS` (line 232). (ran)
- [x] **`RadioButtonGroup.get_id` returns the default value.** The wrapper renders `id="medium"`, or `id=""` with no default. (ran)
- [x] **`data-nav` or `data-call` on anything but a button or anchor throws on click**: "Failed to construct 'FormData': The specified element is not a submit button". `bridge/events.py:313-319` passes the element as the submitter. A `<span data-nav="route">` inside `RawHTML` is enough to trigger it. (browser)
- [x] **Forgotten brackets around page content give a poor error.** `Page(state, "Hello", Button(...))` fails at render with `AttributeError: 'Button' object has no attribute 'extend'`, because the third positional argument is `css`. `Page(state, "Hello", "there")` is accepted silently and "there" is treated as CSS. (ran) **Fixed 15 Nov: `css` and `js` are keyword-only on `Page`, so anything written after the content gets the "Page Content Problem" error with the corrected call.**
- [x] **`Header(2, "Title")` gives "Type Mismatch"** ("'<' not supported...") in place of the header-level error, and `Header("Title", 2.5)` is accepted. (ran)
- [x] **`assert_children(BulletedList(["a", "b"]), ["a", "b"])` fails** with "Too few items (1 < 2)", although the docstring names `BulletedList` items as the use case. (ran)
- [x] **The two state-type checks disagree.** `SiteState.update` warns when `type(a) is not type(b)` (`history/state.py:119`), while verification uses `isinstance` (`payloads/verification.py:215`). A subclass of the state class, or an `int` state replaced by `True`, passes verification and then logs the warning. Docs: `docs/help/errors/state-mismatch.md` covers it as a second case. (ran and browser) **Fixed 15 Nov: both use the exact type, so a subclass state and `True` for an `int` state are error pages.**
- [x] **Empty values and optional parameters are inconsistent.** An upload with no file chosen gives `''` for `str | None` but `None` for `Picture | None`. An empty text box is an error for `int | None` and for a parameter with an `int` default. Empty text for `date`, `time` or `datetime` gives the current date and time. Docs: `docs/reference/route.md#parameter-conversion`, `docs/add/files.md`. (ran; uploads in browser) **Fixed 15 Nov: one rule for a blank number, date, choice or file: `None` when the annotation allows it, else the parameter's default, else the type's empty value (bare dates keep "now"), else an error. Blank text for `str` and `bool` is unchanged.**
- [x] **Code after `start_server()` runs in the browser but not on the computer.** It prints once in the page's Console box and never in the terminal. Docs: `docs/start/how-drafter-works.md` says "On your computer, nothing after it runs." (browser) **Fixed 15 Nov: the docs sentence is corrected, and a warning (terminal and debug panel) names the first line after `start_server(...)`.**
- [x] **Site-wide JavaScript piles up on live reload.** `add_website_js` code runs again on each save in the same document, so listeners accumulate. One key press advanced several cards after a save. Docs: `docs/extend/javascript.md` shows a guard variable. (browser) **Decided 15 Nov: nothing changes by default. Drafter now sends a `drafter-cleanup` window event before a re-run, which the site's JavaScript can use to remove its listeners.**
- [x] **A missing image produces no warning.** A plain broken `<img>`, no error page, nothing in the debug panel. The dev server's terminal shows the 404. (browser) **Fixed 15 Nov: a debug-panel warning ("Image Did Not Load"), once per image address.**
- [x] **`assert_equal` may report the wrong line.** It printed "SUCCESS at line 141" for a 31-line script run from outside the repository. (unconfirmed)

# Documentation site

- [x] **Docs demos hide `print` output.** The plugin passes `--console_mode hover` (`src/drafter/docs/mkdocs_plugin.py:317`). The real flag is `--console-mode`, argparse ignores the misspelling, and demos run in `auto` mode with debug off, so output appears only after the demo's "debug" button is clicked. Docs: notes in `docs/start/debug-panel.md` and `docs/help/printing-and-console.md` that can go once this is fixed. (browser and source)
- [x] **A demo's `js.document` is the docs page.** All demos on a page share one Pyodide hosted by the parent page, so a demo cannot find its own elements by id and `focus()` in a demo scrolls the docs page. This is why the `Canvas` example and four recipes in `docs/extend/javascript.md` are plain fences. (browser) **Fixed 15 Nov: inside an iframe embed, `import js` is the embed's own window. The focus recipe still cannot be a live demo: its script already ran in the demo and pulls the docs page down to it.**
- [x] **Text typed into a demo right after it appears can be lost.** A value typed about half a second after first paint reached the route as an empty string, twice out of twice. With a wait of 2.5 seconds or more it usually worked. (unconfirmed, not diagnosed) **Diagnosed and fixed 15 Nov: the first page is drawn ahead of time and replaced when Python starts, on every site, not only demos. The page is now inert until the loading screen lifts. A script that fills a field must wait for the loading screen to go.**

# Noticed while fixing (15 November 2026)

Found during the fixes above and not fixed. None of these is decided.

- [ ] **`start_server(argv=[...])` does nothing.** The parameter is merged like a setting and no section has a field of that name. Its docstring says it overrides the command line. (read in source)
- [ ] **`start_server(information={...})` with a plain dict crashes the About page.** The setting expects a `SiteInformation`. (ran)
- [ ] **A `bool` parameter fed by an upload with no file gives `True`.** (ran)
- [ ] **No state-type check on the first page after `--reset`.** The history is empty, so any type is accepted once. (read in source)
- [ ] **Most of Drafter's own errors are still untitled.** About fifty `StudentFacingError` sites (audio, camera, colors, pictures, sliders, maps) show "Unusable Value" on an error page and "Drafter could not start" in the terminal box. A default title derived from the component would cover most. (ran)
- [ ] **A built site publishes the path the program was started with.** Every page embeds `DRAFTER_CONFIGURATION.bootstrap.path` as it was typed on the command line, so `python C:\Users\name\site\main.py --compile` puts the user name in `index.html`. (read in source)
- [ ] **`/__drafter_list_files?path=../sibling` answers 500 instead of 400.** The containment check is `str.startswith`, so a sibling folder whose name begins with the project's name passes it and then fails at `relative_to`. Nothing is listed. (ran)
- [ ] **`--additional-files` checks less than `add_website_file`.** It only warns on a missing name and does not compare capital letters: `--additional-files logo.png` copied `Logo.PNG` as `logo.png`. (ran)
- [ ] **A camera with no photo is an error for a bare `bytes` parameter**, while a file field with no file gives `b""`. The blank-value rule treats the two sources differently because `bytes` has an empty value only for uploads. (ran)
- [ ] **The "Disconnected" notice appears two minutes after Stop Server is pressed.** The tab cannot tell a deliberate stop from a lost connection. (browser)
- [ ] **Any reconnect reloads the tab.** A connection dropped by sleep and wake while the program is still running reloads too, and loses the page's state. (read in source)
- [ ] **Once a PyPI library has filled an import, adding the missing file does not help until the tab is reloaded.** Installed packages are found before Drafter's own file finder. The new steps say to reload. (browser)
- [ ] **Automatic installs run before the project's declared packages**, so a declared package whose import name differs from its PyPI name can still trigger a lookup of the import name first. (read in source)
- [ ] **The root is emptied before packages install.** A program with heavy imports probably shows a blank page under the loading screen for the whole install. (inferred)
- [ ] **The route call text for a circular state still contains `<strong>Circular Reference</strong>`** (`safe_repr(escape=False)`). The History tab shows it as text, and it is attached to error envelopes. (ran)
- [ ] **Inside a docs demo, only the demo's own file gets its own `js`.** A helper module the demo imports, `importlib.import_module("js")` and `sys.modules["js"]` still see the docs page. (ran)
- [ ] **The focus recipe in `docs/extend/javascript.md` cannot be a live demo.** Its script runs in the demo, takes the focus, and scrolls the docs page down to it. (browser)
- [ ] **Debug panel leftovers.** The Client File System list is empty until Refresh is pressed; the Files and Tests panels have hard-coded English text; Browser Storage shows hashed keys with nothing marking the current app's rows; the hidden stub panels are still constructed. (read in source)
- [ ] **`tsc --noEmit` reports about twelve errors.** It is not a gate. `DrafterInitOptions` lacks a `packageIndexes` field that `pyodide.index.tsx` uses. (ran)
- [ ] **Steps in dialogs show literal backticks**, and the testing helpers' messages still say "a int". (browser, ran)
