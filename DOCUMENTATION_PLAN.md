# Documentation Plan for `src/drafter/`

Status of this document: working plan, generated 2026-07-22 from a full audit of all 159
Python files (~21k lines) on the `v2-pyodide` branch. Audit = an AST-based coverage scan
(every public module/class/function/method/top-level constant) plus a manual quality pass
over every file that *has* docstrings, checking them against the actual code.

Target style: **Google-style docstrings** for modules, classes, class attributes,
functions/methods, and top-level constants/variables.

### Quality findings (files that HAVE docs)

The quality audit found ~80 concrete defects. The dominant failure modes, in order:

1. **Refactor drift** — docstrings written for earlier signatures that survived the v1→v2
   rewrite verbatim: phantom parameters, wrong return types (docs say "returns HTML
   string" where code returns `Page`), attributes that were renamed/removed.
2. **Attributes-section rot** — dataclass fields added after the class docstring was
   written are silently missing (`Request.button_pressed`, `Theme.metadata`,
   `SiteState.history`, `ResponseEvent.formatted_page_content`, …). Class Attributes
   sections rot faster than function Args.
3. **Sibling copy-paste drift** — docs copied from a similar class and incompletely
   adapted (`DateTimeInput`←`DateInput`, `Button`←`Link`, `precompile_server` from a
   former free function).
4. **Two generations of docs** — Pyodide-era files (`components/map.py`, `audio.py`,
   `geolocation.py`, `bridge/persistence.py`, `router/parameters/*`,
   `client_server/commands.py`) are exemplary; pre-rewrite files carry terse or stale
   docs (old `POSITIONAL_ARGS`/`CONTENT_ARGS` argument system, Skulpt references,
   pre-`RenderPlan` design musings).
5. **TODOs and placeholders inside docstrings** — including a literal autogenerated
   `_description_` stub (`bridge/events.py:collect_form_data`), a `_type_` placeholder
   (`files/opening.py`), TODO checklists as module docstrings (`styling/styling.py`,
   `data/details/recursive_type_describer.py`), and one already-implemented TODO
   (`history/state.py`).
6. **Docs for code that doesn't exist** — `testing/assertions.py` module docstring
   advertises six assertion functions that were never written, and `assert_page` has a
   full docstring on an empty no-op body; config docstrings reference `AppBackendConfig`
   and a "FileSystem interface" that exist nowhere.

Style is otherwise consistently Google: only isolated deviations (Sphinx `:class:`/
`:data:` roles in `data/errors.py`, `data/response.py`, `client_server.py`; a
`Parameters:` list in `testing/assertions.py`; an `Args: (None)` in
`payloads/payloads.py`; recurring `**kwargs (dict):` mis-annotations).

### Tooling gaps

- `ruff` runs only `E4/E7/E9/F` — **no docstring rules enforced** (`pyproject.toml:153`).
- `mkdocstrings-python` is a dev dependency but **commented out** in `mkdocs.yml:47` —
  docstrings render nowhere.
- Legacy Sphinx tree in `docsrc/` (conf.py, .rst) coexists with the mkdocs setup.

### Phase 4 — Enforcement and rendering (keep it fixed)

1. **Ruff pydocstyle rules**: add `"D"` to `select` with
   `[tool.ruff.lint.pydocstyle] convention = "google"`. Roll out per-package via
   `per-file-ignores` (start with Tier 1 packages, expand as phases complete) so CI
   goes green immediately and ratchets.
2. **Signature-drift checking** — the audit's dominant failure mode is mechanically
   detectable:
   - Ruff's preview `DOC` rules (pydoclint port: `DOC101/102/201/501`-family) check
     Args-vs-signature and Returns/Raises presence; or run `pydoclint` directly with
     `--style=google`.
   - Extend the audit script (see below) into `tools/doc_drift.py` for the check ruff
     doesn't have yet: **Attributes-section vs dataclass-field** comparison — this
     catches the `Request.button_pressed` class of rot. Wire both into `just lint` and
     `.github/workflows/test_and_lint.yml`.
3. **Render the docs**: re-enable `mkdocstrings` in `mkdocs.yml` (already a dep, with
   `mkdocs-gen-files` + `mkdocs-literate-nav` — clearly the original intent) and
   generate an API reference section; set
   `mkdocstrings-python` `docstring_style: google`. Rendering is also the best QA:
   badly-formed sections become visible immediately.
4. **Coverage ratchet** (optional): `interrogate --fail-under N` in CI, raising N as
   phases land; or track via the audit script's totals.
5. Retire `docsrc/` once mkdocs covers it (per the Phase 0 decision).
